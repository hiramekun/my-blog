# 他社ロゴを使わない理由

プロフィールページ（`apps/profile`）のリンク集は、**各サービスのロゴを出さず、
サービス名のテキストで並べている**。リンクを増やすときも同じ方針で足すこと。

## なぜロゴを使わないか

このサイトのアイコンは `currentColor` で描画する。テーマの地色（ライト/ダーク）に
合わせて単色で塗るということで、**元のロゴの色は再現しない**。

ところが、下に挙げたとおり各社の条件はまちまちで、色の変更や改変を明示的に
禁じているサービスがある。条件を満たせるものと満たせないものが混在すると、

- ロゴが出るサービスと出ないサービスが並ぶ不揃いな見た目になる
- 追加するたびに 1 件ずつ商標の条件を調べ直すことになる

ので、**全部テキストに揃えた**。商標を一切扱わなくなるので、リンクを増やすのも楽になる。
リンク集は自分のサイトも外部サービスも同じカードで並べているので、この点でも揃う。

フルカラーのロゴを `<img>` で並べる案もあるが、単色のデザインシステムに合わないので採らない。

## 調べた結果（2026-08-30 時点）

### GitHub

条件は満たせる。公式が [primer/octicons](https://github.com/primer/octicons) で
MIT ライセンス（Copyright (c) GitHub Inc.）のアイコンセットを配布しており、
明色用の黒版と暗色用の白版があるので、単色で地色に合わせるのは同じ扱いになる。
ロゴポリシーは <https://github.com/logos>。

条件としては使えるが、他が揃わないので上記のとおりテキストに統一した。

### X

<https://about.x.com/en/who-we-are/brand-toolkit>

`about.x.com` はブランドページもガイドライン PDF も HTTP 402 を返し、**原文を確認できなかった**。
二次情報では "You may use the X brands solely for the purposes expressly authorized by X"
という許諾ベースの書き方で、個人サイトからのプロフィールリンクを明示的に認めた記述は
見つからなかった。条件を自分で確認できていないので使わない。

### はてなブログ

<https://brand.hatena.co.jp/hatenablog>

ロゴデータとガイドラインは Google Drive で配布。条件（原文）:

- 「原則として、データの編集、変更、改変等はせず、そのまま利用してください。」
- 「法令及び本ガイドラインを遵守し、当社の権利を侵害しない態様でご利用ください。」

単色化は「改変」にあたる。商用利用は問い合わせが必要とされている。

### AtCoder

<https://info.atcoder.jp/logoguide>

条件（原文）:

- 「加工（色の変更・装飾・歪曲）はしないでください。」
- 「文章中での利用はしないでください」
- ロゴファイルへの直リンク禁止

色を変えられず、ラベルの隣に置く形も「文章中での利用」に読める。
そもそもロゴがワードマーク（"AtCoder" の文字組み）なのでアイコン枠に合わない。
判断に迷う場合の問い合わせ先: <https://atcoder.zendesk.com/hc/ja/requests/new>

## 注意

ここに書いたのは公開されているガイドラインを読んだ結果であって、法的な助言ではない。
各社の条件は変わりうるので、方針を変えるときは上記の一次情報を直接確認すること。
