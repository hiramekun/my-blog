# verify-site

このリポジトリは 2 つの静的サイト（Next.js）を持つモノレポ。UIに変更を加えたあと、
ローカルで表示が崩れていないかをブラウザで確認するための手順。ビルドやlintが通っていても、
レイアウト崩れやスタイルの欠落は検出できないため、代表的なページを実際に描画して目視する。

| サイト | ワークスペース | devサーバー | 本番 |
| --- | --- | --- | --- |
| プロフィール（リンク集） | `apps/profile` | `http://localhost:3001/` | https://hiramekun.dev/ |
| ブログ | `apps/blog` | `http://localhost:3000/` | https://blog.hiramekun.dev/ |

`basePath` は使っていないので、どちらもルート（`/`）で配信される。

## 手順

1. **devサーバーを起動**
   - `preview_start` を name `blog` または `profile` で呼ぶ（`.claude/launch.json` に定義済み）。
   - 共有のデザインシステム `packages/theme/globals.css` を触ったときは **両方** 起動して確認する。
   - すでに起動済みなら再利用される。

2. **変更したサイトの代表ページを開いて screenshot で目視確認**

   ブログ（共通コンポーネントの変更は全ページに波及するので最低この4種類）:

   | ページ種別 | URL 例 |
   | --- | --- |
   | ホーム（記事一覧） | `http://localhost:3000/` |
   | 記事詳細 | `http://localhost:3000/posts/llm-thoughts` |
   | アーカイブ | `http://localhost:3000/archive/2025/08` |
   | カテゴリ | `http://localhost:3000/category/AI` |

   確認するポイント：
   - ヘッダー（他サイトへの About / Notes リンクを含む）・サイドバーが表示されているか
   - 記事カードのレイアウト・タグ・日付・抜粋が崩れていないか
   - 記事詳細では Markdown（見出し・コードブロック・`**「...」**` の太字強調）が正しく描画されているか
   - アーカイブ／カテゴリの並び順が期待どおりか

   プロフィール（`http://localhost:3001/`）:
   - アバター・名前・肩書き・自己紹介が中央に揃っているか
   - Links のカードが 6 枚並び、hover で持ち上がるか
   - 各カードのタイトル・説明文・右上の矢印が崩れていないか

3. **ライト／ダークの両方を確認**
   - テーマは `prefers-color-scheme` で切り替わる。`resize_window` の `colorScheme` を
     `light` / `dark` の両方にして、コントラストが落ちていないかを見る。
   - とくに記事本文のコードブロック・引用・表は、両方で読めることを確かめる。

4. **レスポンシブを確認**
   - `resize_window` を `mobile` にして、1カラムに落ちること・横スクロールが出ないことを見る。

5. **コンソールエラーを確認**
   - 各ページで `read_console_messages`（`onlyErrors: true`）を呼び、エラーが無いことを確認する。

6. 崩れやエラーがあれば原因を特定して修正し、2〜5を再確認する。

## 補足

- 実際に存在する記事ID・カテゴリ名は `posts/` 配下のファイルと frontmatter の `tags` に依存する。
  URL例が 404 になる場合は、`getAllPostIds` / `getAllCategories` 相当の実データに合わせて差し替える。
- 既存の記事にはコードブロック・表・引用が無い。本文まわりのスタイルを変えたときは、
  それらを含む Markdown を `posts/` に一時的に置いて確認し、終わったら消すこと。
- 確認が終わったら `preview_stop` でサーバーを停止してよい（起動したままでも支障はない）。
